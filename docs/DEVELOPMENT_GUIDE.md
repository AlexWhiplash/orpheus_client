# Orpheus Client — гайд для разработки

## Принципы
- **Минимальные изменения**: правим только то, что нужно для задачи.
- **Контракты поведения** фиксируются тестами (unit/widget).
- **Сервисы** не должны напрямую зависеть от UI.
- При изменениях публичного поведения/UX обновляются соответствующие разделы `docs/`.

## Инварианты безопасности, которые надо держать в голове
- **Лок — оверлей, а не экран.** `LockScreen` рисуется поверх Navigator (`main.dart:1247-1256`).
  Маршруты, открытые до лока, остаются смонтированными с расшифрованными данными, поэтому при смене
  личности сессии их снимает `dropRoutesAboveHome()` (`main.dart:129`; точки вызова — duress-вход,
  завершение wipe, настоящий PIN после duress). Новый экран автоматически попадает под этот
  инвариант, но его `State` не должен переживать снятие: продолжения `await Navigator.push(...)`
  обязаны быть под `if (!mounted) return`.
- **Duress-гейт не наследуется.** Гейт стоит в `DatabaseService`. Любой НОВЫЙ источник данных —
  серверный API, `SharedPreferences`, кеш сервиса — под duress отдаёт реальные данные, пока для него
  не добавлен свой гейт (так утекли Rooms и чат поддержки). Для сетевых сервисов приём — обнулить
  pubkey (`rooms_service.dart:25`); ошибку на экране показывать нельзя, если она отличима от
  обычного сбоя сети (`support_chat_service.dart:62`).
- **Ничего не признавать.** UI под duress не должен подтверждать, что код принуждения/удаления
  настроен, а лог — называть режим (`security_settings_screen.dart:201-203`, `main.dart:970`).
  Сеттер-no-op обязан сопровождаться проверкой по конфигу, иначе экран соврёт «применено».
- **После wipe нельзя писать.** `dispose()` экранов выполняется уже после стирания, поэтому любая
  запись в БД/prefs из `dispose` идёт под гард «личность ещё есть» (`call_screen.dart:1250`,
  `room_chat_screen.dart:112`) — иначе пересоздаётся SQLCipher-база с новым ключом.

## Структура проекта (кратко)
Подробно: `docs/ARCHITECTURE.md`.

- `lib/` — приложение (экраны, сервисы, модели, виджеты, тема)
- `test/` — unit/widget тесты
- `android/` — Android‑часть (Gradle, манифесты, ресурсы)
- `scripts/` — вспомогательные скрипты (hooks, автокоммит и т.п.)

## Процесс изменений
### Перед изменениями
- Понять затрагиваемые контракты (что должно оставаться верным).
- Определить, какие тесты подтвердят “сделано”.

### Во время изменений
- Обновлять/добавлять тесты вместе с кодом.
- Избегать “скрытых” изменений поведения.

### После изменений
- Прогнать тесты (см. `docs/testing/README.md`).
- Обновить артефакты процесса:
  - `CHANGELOG.md` (секция `Unreleased`)
  - `AI_WORKLOG.md`
  - `docs/` (если меняется “как работает/как пользоваться”)
