# Device-чеклист перед релизом (накоплено за сессию рефакторинга)

Всё ниже — то, что **нельзя проверить сборкой/тестами**, только на реальном
устройстве. Правило владельца: **не выпускаем в релиз, пока всё не победим.**

Собрать **release**-APK (`flutter build apk --release`, подписан реальным
keystore — OPS-1) и гонять на матрице устройств. Матрица (квирки кластеризуются
по OEM и версии Android):

- [ ] Pixel / чистый Android
- [ ] Samsung (One UI)
- [ ] Xiaomi (MIUI/HyperOS)
- [ ] Android 13, 14, 15 (разные)

> **minSdk поднят 23 → 24: Android 6.0 больше НЕ поддерживается.** Проверить, что
> приложение ставится на Android 7+ и отсутствует в сторе для Android 6.

## 1. Secure storage v10 (чистая установка)

Все ставят с нуля (решение владельца) → тест обновления v9→v10 поверх **пропущен**,
старый APK не нужен. Проверяем только путь чистой установки.

- [ ] Пройти раздел **«Чистая установка»** в
  [SECURE_STORAGE_V10_CHECKLIST.md](SECURE_STORAGE_V10_CHECKLIST.md): создание
  аккаунта на современных шифрах, вход по PIN после перезапуска и **после ребута
  устройства** (у v10 исторически ломалось «чтение после boot»), panic-wipe.

## 2. Звонки — мажоры плагинов + вынос логики в CallSessionController

Ядро, переписанное в этой сессии (callkit 2→3, перевязка на контроллер, 2
пойманных ревью регресса реконнекта). Проверять придирчиво.

- [ ] **Исходящий звонок**: соединяется, слышно в обе стороны.
- [ ] **Входящий звонок (приложение открыто)**: CallKit-экран, приём, звук.
- [ ] **Входящий звонок из УБИТОГО состояния**: доставка через push-сервис
  (specialUse FGS, без FCM), CallKit поверх локскрина, приём, звук.
- [ ] **Full-screen входящего с локскрина** (enableCallMode).
- [ ] **Микрофон при свёрнутом приложении во время разговора** (нативный
  CallAudioService FGS, Android 14 while-in-use) — собеседник продолжает слышать.
- [ ] **Реконнект при смене сети Wi-Fi ↔ cellular во время звонка** — звонок НЕ
  залипает на «Reconnecting...», аудио восстанавливается. *(Здесь ревью нашло 2
  бага — проверить особенно тщательно: (а) реконнект не умирает после 1 попытки;
  (б) при исчерпании попыток экран авто-закрывается.)*
- [ ] **Исчерпание реконнекта**: после серии неудач экран показывает «Failed» и
  **сам закрывается** через ~2с.
- [ ] **Собеседник кладёт трубку** → экран закрывается, статус-сообщение в чате.
- [ ] **Отклонение/отмена** входящего/исходящего.

## 4. Биометрия и PIN (local_auth 2→3, Argon2id PIN — SEC-8)

- [ ] **Разблокировка по биометрии** (отпечаток/лицо) на локскрине и в настройках.
- [ ] **Вход по PIN** (Argon2id, verifyPin теперь async) — задержки нет заметной.
- [ ] **Duress-код** → пустой профиль (полный сценарий — см. §7).
- [ ] **Auto-wipe** (N неверных попыток PIN) → данные стираются, открывается экран
  приветствия. Это единственный РАБОЧИЙ путь экстренного стирания с локскрина.
- [ ] ⚠️ **Wipe-код с локскрина НЕ РАБОТАЕТ** — известный открытый баг: диалог

  `MaterialApp.builder` (`main.dart:1247-1256`), где нет Navigator-предка. Пункт не
  отмечать «пройдено», пока баг не закрыт.
- [ ] **LOGIC-6:** после серии неверных PIN включается блокировка (30с/1м/...).
  **Перевести системные часы вперёд — блокировка НЕ снимается** (монотонные часы).

## 7. Duress mode (усилен в 1.1.8+45) — только руками

Подготовка: PIN задан, duress-код задан, есть ≥1 контакт с историей, ≥1 комната, есть
переписка в «Чате с разработчиком».

- [ ] **Открытый чат не переезжает в duress**: открыть чат с историей → заблокировать →
  войти по **duress-коду** → виден главный экран с пустым списком, чата НЕТ (ни
  содержимого, ни возврата «назад»). (`main.dart:967-990`, `dropRoutesAboveHome` `main.dart:129`)
- [ ] **Экспорт аккаунта под duress**: Профиль → «Экспорт аккаунта» → спрашивает **PIN
  приложения** (НЕ отпечаток и НЕ код-пароль телефона), duress-код не принимается, ключ
  не показывается. (`settings_screen.dart:139`)
- [ ] **Комнаты под duress**: вкладка «Комнаты» пустая, точки непрочитанного нет;
  создание/вход по инвайту даёт обычную ошибку связи. (`rooms_service.dart:25`,
  `home_screen.dart:41-42`)
- [ ] **Чат с разработчиком под duress**: пустой, БЕЗ красной плашки ошибки.
  (`support_chat_service.dart:62`)
- [ ] **Экран «Безопасность» под duress**: секции «Код принуждения» и «Код удаления»
  видны и предлагают «Установить …» (как будто не настроены), кнопок «Отключить» нет.
  (`security_settings_screen.dart:201-203`)
- [ ] **Настройки под duress — no-op**: auto-wipe, «жест паники», биометрия, таймер
  блокировки, срок хранения сообщений, «Имя звонящего на локскрине» — не сохраняются,
  переключатель отскакивает (это ожидаемо); после входа по настоящему PIN настройки
  жертвы не изменились. (`auth_service.dart:477,486,497,513,588`,
  `security_settings_screen.dart:304`)
- [ ] **Возврат по настоящему PIN**: из duress-сессии заблокировать → настоящий PIN →
  профиль реальный, открытые в duress экраны сброшены. (`main.dart:938-940`)
- [ ] **Регресс обычного unlock**: БЕЗ duress — открыть чат → автоблокировка → настоящий
  PIN → возвращает **в тот же чат** (маршруты НЕ сбрасываются).
- [ ] **Регресс звонка с локскрина**: входящий при заблокированном приложении → ответить
  → PIN → звонок соединяется. Правки duress трогали pending-call (`main.dart:979-986`) —
  проверять придирчиво, 3-5 раз.
- [ ] **Регресс после wipe**: открыть чат → auto-wipe → на экране приветствие, чата нет;
  перезапуск даёт новый пустой аккаунт, журнал звонков пуст (`main.dart:821`,
  `call_screen.dart:1250`, `room_chat_screen.dart:112`).
